# 页面设计

新页和结构调整在查询组件前确定以下决策。局部修改沿用已有设计。

1. 用用户要完成的任务组织内容。明确各窗格职责、默认显示什么、用户先看什么和接下来能做什么。共享对象用同一个稳定 ID 连接列表、详情和操作。
2. 从 discover 返回的 Pattern 与槽位确定内容区域。用实际内容宽度推演一条有长标题和真实字段的列表行，或一个关键业务分组。明确主字段、次要信息、对齐轴、间距、换行与截断。沿用 Pattern 管理的内边距和滚动。
3. 按用途分配视觉强调。只有 2–4 个可切换的一级入口时使用 Primary Navigation Item，单应用入口由标题栏标识。主任务入口优先，筛选、切换和反馈采用各自的标准控件与状态。业务摘要和提示靠近它们解释的结果，保留关键操作和结果的浏览空间。
4. 按已确定的用途查询组件 ID 和场景。对复用能力存疑时核对实际输出。仅在公开接口无法表达业务内容或联动时，按 [业务扩展](business-extension.md) 记录缺口并在所属分组组合。私有样式遵循 Token 语义，颜色、尺寸与圆角分别选其适用 Token。

简单页面直接用分组目的和顺序表达。多模块联动或密集业务页面，把区域职责、阅读顺序、优先级、密度和联动关系写进现有 `design`，用 `states` 表达主任务涉及的默认、选中、空结果及其他实际需要的状态。具体字段见 [消费输入](consumer-input.md)。代表性内容行的决策落在原分组或业务实现中。

Pattern B 示例：邮箱导航提供文件夹，列表负责搜索和选择，阅读区展示所选邮件。中栏先推演长标题、日期、筛选和结果在同一宽度的表现。智慧摘要用于定位相关邮件，点击来源后列表选中与阅读内容应指向同一封邮件。其他业务按自己的任务排序。

## 按需提取 Block

Workflow 决定是否重新设计组合（新页、或 Demo 规范化时确有结构调整）；Task 提示业务候选；最终 Pattern 限定可放置的区域。发现阶段只返回候选的用途，确认需要后运行 `discover-page.mjs --task "<任务>" --block <ID>`。适用其他 Workflow 或非默认 Pattern 时，保留原发现命令的路由参数。

Block 说明窗格内部的业务组合、操作优先级与状态，不接管 Pattern 槽位、对齐轴和滚动，不改变组件外观。生成仍使用现有的 groups、composition、interactions 与业务模块。

邮件与记录管理任务可在 Pattern B 的 `secondary-list` 按需提取「分组列表」（沿用现有 ID `grouped-mail-list`）。业务字段与分组依据由项目决定；有详情区时用稳定的对象 ID 同步选择。左侧导航有带标题且可独立折叠的分组时，按需提取 `collapsible-navigation-group`。

Pattern B 的当前对象有多项标题栏操作、需要随宽度折叠时，按需提取 `titlebar-action-overflow`。按操作优先级填写 `detailActions`，由 Titlebar 管理「更多」及窗口控件。
